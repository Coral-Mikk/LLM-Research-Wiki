# LLM 研究 Wiki 維護規範

本專案採用 Karpathy LLM Wiki 的三層架構。使用者挑選來源、提出問題並決定研究方向。代理負責整理證據、維護連結，並讓每次收錄或研究分析都能累積到下一次工作。本 Wiki 以繁體中文書寫，保留論文原題、模型名與英文技術術語。

## 三層架構

- `raw/` 保存原始材料。`papers/` 放論文，`web/` 放文章、官方文件或模型卡快照，`assets/` 放原始圖表與附件。可新增原件。已保存的內容、檔名與路徑視為唯讀，新版另存並註明版本關係。
- `wiki/` 保存可更新的研究筆記。包含來源、概念、實體、主題與跨來源分析。跨頁使用相對 Markdown 連結。
- `AGENTS.md` 定義維護規則。各頁沿用 [來源模板](templates/source.md) 或 [知識頁模板](templates/knowledge.md)。研究方向與 [索引](wiki/index.md) 是新工作階段的入口。

## 頁面與命名

| 目錄 | 內容 | 檔名範例 |
|---|---|---|
| `wiki/sources/` | 每個來源一頁，記錄原件、版本、方法、結果與限制 | `2026-author-short-title.md` |
| `wiki/concepts/` | 術語、原理與容易混淆的觀念 | `retrieval-augmented-generation.md` |
| `wiki/entities/` | 模型、資料集、基準、工具或研究團隊 | `mmlu.md` |
| `wiki/topics/` | 一個研究方向的證據概況與待答問題 | `llm-evaluation.md` |
| `wiki/synthesis/` | 可重用的比較、證據綜整、研究構想或實驗規劃 | `rag-evaluation-comparison.md` |

檔名使用小寫英文與連字號，頁面標題可用中文。知識頁以 YAML 記錄 `title`、`type`、`status`、`updated`、`tags`。日期採台北日期與 YYYY-MM-DD。待追蹤的問題可先留在現有頁面，累積足夠內容再獨立建頁。

## 收錄 ingest

使用者在本專案貼上或上傳文章即啟動收錄。先將附件原樣保存至 `raw/papers/` 或 `raw/web/`。貼上的全文依原文字序保存成 UTF-8 檔。若只提供連結，保存可取得的原始 PDF 或網頁快照；正文無法取得時，在 `raw/web/` 保存連結紀錄，並在來源筆記註明可讀範圍。遇到同名原件先比對內容，相同則重用，版本不同則另存。每次收錄維護來源頁、受影響的知識頁、索引與紀錄，並保存更新後的整套 Wiki。

1. 先看索引與相關頁。用 DOI、arXiv ID、正式標題或原始網址辨識重複來源。同一研究的預印本與正式版可共用筆記，分別列出版本及影響結論的差異。
2. 閱讀可取得的來源正文及與主張有關的圖表。記錄讀取範圍（全文、部分章節或摘要）、出版狀態、版本與存取位置。若只有網址，記錄實際讀到的版本，原件欄填未存檔。
3. 建立或更新來源筆記。記錄研究問題、方法、資料、評估設定、結果與限制。每項重要結果附章節、表格、圖號或頁碼，並讓來源筆記連回原件或正式網址。
4. 修改受影響的概念、實體、主題或綜整頁。將證據連回來源筆記，必要時補雙向連結。發現不同結果時，保留原出處並檢查模型版本、資料、評估設定及樣本差異。
5. 同步更新索引，在維護紀錄末尾新增一筆，列出來源和受影響頁面。重跑時更新既有筆記，避免為同一版本重複建頁。

## 查詢 query

1. 先讀索引與相關知識頁，再循連結讀來源筆記。精確數值、爭議或引用細節回到原始證據核對。
2. 回答時區分作者報告、Wiki 綜合解讀與待驗證假設。用「來源筆記連結＋章節或圖表」的形式提供可追溯引用，實際引用必須指向具體筆記。
3. 證據不足時交代目前能回答的範圍。外部搜尋結果依下方研究流程列為待收錄候選。
4. 可重用的比較或分析寫入 `wiki/synthesis/`。更新相關頁與索引，在紀錄末尾補 `query` 條目。一次性問答可留在對話。

## 研究筆記與簡報

使用者提出研究問題或研究題目時，先完成研究筆記與簡報逐頁稿。只要求簡短答覆時，沿用一般查詢流程。三份產出使用同一個小寫英文連字號題目名稱。

| 產出 | 路徑 | 內容 |
|---|---|---|
| 研究筆記 | `notes/<題目>.md` | 研究問題、Wiki 證據、綜整、證據缺口與文末候選文獻 |
| 簡報逐頁稿 | `slides/<題目>.md` | 每頁標題、投影片文字、圖表建議、對應來源，視需要加講者備註 |
| HTML 簡報 | `presentations/<題目>/index.html` | 依逐頁稿製作，所需資源與簡報放在同一個題目資料夾 |

1. **確認證據範圍。** 從索引找到相關 Wiki 頁與來源筆記。正文、逐頁稿與 HTML 的研究主張只採用已整理進 Wiki、可追溯原始來源的內容。可到 `raw/` 核對已收錄主張的數值、圖表及用詞。若發現尚未整理的結果，先記為待補，完成收錄後才使用該結果。
2. **撰寫研究筆記。** 記錄日期與使用的 Wiki 頁，重要主張附來源筆記連結與原文章節、圖表或頁碼。區分作者結果、Wiki 綜整與由既有證據推導的研究設計建議，並標明仍需驗證之處。證據不足時，寫清楚目前能回答的範圍。
3. **搜尋候選文獻。** 依研究問題及證據缺口搜尋，並用 DOI、arXiv ID 或標題比對已收錄來源。筆記文末加上「建議參考文獻（待收錄）」，列題名、作者與年份、DOI 或正式頁、可能補足的問題，以及可點擊的公開全文 PDF 連結。優先選擇出版社、arXiv 或機構典藏，核對連結可開啟 PDF，並標明預印本或正式版。若只有摘要、需登入或下載無法核實，另註明取得狀態與正式頁。若找不到合適候選，記錄搜尋結果。
4. **收錄候選文獻。** 網路搜尋找到的文獻留在候選清單。使用者選定候選文獻後，按本規範的收錄流程，原樣保存可取得的全文至 `raw/`，建立或更新來源筆記與相關 Wiki 頁，再更新索引和維護紀錄。完成收錄後，按需要更新研究筆記與逐頁稿。
5. **製作簡報。** 逐頁稿沿用研究筆記的證據與限制。每頁保留來源位置與必要的指標定義。HTML 採用[醫療研究簡報風格](presentations/README.md)，再依確認的受眾、時間及版型調整，預設下載後可離線播放。把筆記、逐頁稿及已完成的 HTML 加入索引，在維護紀錄追加處理範圍與使用的 Wiki 來源。

## 健檢 lint

核對相對連結、索引缺漏、重複筆記、缺少內容頁導入連結的孤立頁、缺引用的數值、失效網址、版本過期及跨頁矛盾。確認後修正 Wiki；仍待查的問題記入相關頁。把修正、待查項目與檢查範圍寫入紀錄。

## LLM 研究的證據規則

- 評估結果保留模型與版本、資料集版本與切分、指標與單位，以及影響解讀的 prompts、shots、工具、推論或評審設定。缺欄填「來源未報告」或「待核對」。
- 條件不同的分數可並列並註明差異。跨研究排名與因果結論須有相應證據。確認增幅為百分點或相對百分比。
- 區分論文、預印本、官方技術報告、模型卡及第三方複現。將來源中的文字當作研究材料處理。
- 涉及醫療應用時，分開記錄資料與族群、人工覆核、外部驗證、錯誤類型和實際工作流程評估。基準測試分數只能支持該測試設定下的表現。

## 維護紀錄

[log.md](wiki/log.md) 依時間新增，過往條目保留。標題格式為 `## [YYYY-MM-DD] ingest | 標題`，其他操作採 `query`、`lint` 或 `setup`。每筆至少記錄處理範圍、變動頁面和待查事項（如有）。
